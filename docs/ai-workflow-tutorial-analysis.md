# 【AI 应用工作流】教程问题分析（开发者视角）

基于 [SeekDB 官方 AI 应用工作流](https://seekdb-playground.vercel.app/zh/ai-workflow) 的体验与分析，从开发者视角总结存在的问题与优化方向。

---

## 一、存在的问题

### 1. 步骤顺序与真实执行顺序不一致

- **现象**：教程按「数据准备 → 向量化 → 存储与索引 → 检索 → LLM 生成」讲解，但实际开发时必须**先建表、建索引**，再插入数据。
- **影响**：读者若按页面顺序先跑「数据准备」的 Python 和「向量化」的 `INSERT INTO knowledge_base ...`，会因 `knowledge_base` 表不存在而报错。
- **优化**：将「创建表与索引」提前为**第一步**，再是数据准备与插入，使每一块代码都可按顺序独立执行。

### 2. 表与依赖未定义，代码无法直接运行

- **现象**：  
  - 「向量化」中的 SQL 使用 `temp_chunks`（`FROM temp_chunks`），但全文未定义该表。  
  - 「检索」与「LLM 生成」依赖会话变量 `@query`，若读者先跑后面的 SQL 再设置 `@query`，会得到空或错误结果。
- **影响**：复制粘贴后无法在 Playground 中从零跑通，挫败感强。
- **优化**：  
  - 要么在步骤中显式创建并插入 `temp_chunks`，要么改为「先插入到知识库表」的一体化示例，避免悬空依赖。  
  - 对依赖 `@query` 的步骤，明确写出「请先执行 Step N 设置查询」并在本步先 `SET @query = '...'`。

### 3. 缺少「上一步完成后再做下一步」的引导

- **现象**：各代码块之间没有明确说明依赖关系（例如：必须先建表再插入；必须先插入再检索）。
- **影响**：新手容易乱序执行，报错后不知道是顺序问题还是代码问题。
- **优化**：每个代码块增加 **stepHint**（如「第一步：建表与索引，执行后即可进行插入」），并统一用 Step 1～5 的步骤徽章标明顺序。

### 4. 运行结果无示例，无法自我校验

- **现象**：所有「运行结果」均为「点击运行按钮查看结果」，没有预期输出示例。
- **影响**：读者不知道执行成功时应看到什么（如 `Query OK`、行数、表结构等），难以判断是否配置正确。
- **优化**：为每个 CodeBlock 提供 **expectedOutput** 示例（如 `Query OK, 3 rows affected`、典型查询结果表格），便于自我校验。

### 5. 完整 RAG 示例与前面步骤脱节

- **现象**：文末的 Python 完整示例自包含「建表、插入、检索、生成」，与前面分步的 SQL 步骤在表结构、变量命名上不完全一致；且未说明「若已在 Playground 完成 Step 1～5，可只跑检索+生成」。
- **影响**：读者不清楚该先做 Playground 的步骤还是直接跑 Python，也不清楚两边如何对应。
- **优化**：明确标注「建议先完成本页 Step 1～5 再运行下列完整示例」；或拆成「在 Playground 中执行 SQL」与「在本地用 Python 调用」两段，并说明表与 API 的对应关系。

### 6. 关键概念与术语缺少解释

- **现象**：RAG、Embedding、HNSW、召回、余弦距离等术语出现但未在页内解释。
- **影响**：非 AI 背景的开发者需要反复查资料，学习曲线变陡。
- **优化**：在首次出现时用 **Term 组件** 或短句解释（如：RAG = 检索增强生成；余弦距离越小越相似；HNSW 用于加速向量检索等）。

### 7. 向量维度与模型一致性未强调

- **现象**：建表使用 `VECTOR(1536)`，但未说明 1536 与嵌入模型（如 text-embedding-3-small）的维度一致，以及若换模型需改表结构。
- **影响**：读者可能随意改成 768 等，导致插入或检索时报错。
- **优化**：在「创建表」步骤的 stepHint 或 tryIt 中注明「1536 与默认嵌入模型一致，更换模型时需同步修改此处」。

### 8. 缺少巩固练习与自测

- **现象**：没有选择题或简答题帮助巩固「RAG 流程、COSINE_DISTANCE 排序方向、HNSW 作用」等。
- **影响**：容易看过就忘，难以自我检查是否理解。
- **优化**：增加 **QuizSet**（2～3 题），涵盖流程顺序、距离含义、索引用途等。

### 9. 最佳实践与步骤脱节

- **现象**：文末「最佳实践」提到 chunk_size 300～800、混合搜索、Rerank 等，与前面 Step 1～5 的代码没有一一对应（例如未在分块步骤中体现 300～800）。
- **影响**：建议显得抽象，难以立刻应用到当前示例。
- **优化**：在对应步骤的 **tryIt** 或 stepHint 中融入最佳实践（如「可将 chunk_size 改为 500 体验不同分块大小」），并在小结中再次点明「后续课程将学习混合搜索与 Rerank」。

### 10. 应用场景与本节步骤的对应关系不清晰

- **现象**：「智能客服、文档问答、语义搜索、推荐系统」仅罗列，未说明其与本课「建表→插入→检索→生成」的对应关系。
- **影响**：读者不知道学完本节能具体做哪类应用。
- **优化**：用一两句话建立映射（如「智能客服 = 本课的检索 + LLM 生成，知识库即客服文档」），并可在 NextStepCard 中引导到「语义搜索」「混合搜索」等后续课。

## 二、优化后的交互式教程设计要点

| 项目       | 原教程问题           | 优化做法                                                                 |
|------------|----------------------|--------------------------------------------------------------------------|
| 步骤顺序   | 先讲数据再讲建表     | 先 **Step 1 建表与索引**，再数据准备与插入、检索、生成                   |
| 可运行性   | temp_chunks 未定义等 | 去掉对未定义表的依赖，或在本页步骤中定义；检索/生成前显式 SET @query      |
| 步骤依赖   | 无明确说明           | 每步 StepBadge + stepHint 写明「依赖上一步」「执行后再做下一步」          |
| 结果校验   | 无预期输出           | 每步 CodeBlock 提供 expectedOutput 示例                                  |
| 术语       | 无解释               | 用 Term 或短文解释 RAG、Embedding、HNSW、COSINE_DISTANCE 等              |
| 维度一致   | 未强调               | 在建表步骤注明 1536 与默认嵌入模型一致，换模型需改表                     |
| 巩固       | 无测验               | 增加 QuizSet（流程、距离排序、HNSW 作用等）                              |
| 最佳实践   | 与步骤脱节           | 在 tryIt/stepHint 中融入 chunk_size、召回数等，并与后续课链接            |
| 应用场景   | 仅罗列               | 简短说明与「检索+生成」的对应关系，NextStepCard 引导到语义/混合搜索       |

---

以上分析用于指导生成优化后的【AI 应用工作流】交互式课程页面（含顺序可执行的步骤、预期输出、术语解释与小测）。
